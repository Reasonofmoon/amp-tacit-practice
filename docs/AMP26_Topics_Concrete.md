# AMP 26기 — 주제별 구체 설명서

> **목적:** “정보 흐름”, “자산화” 같은 추상어를 **오늘 할 수 있는 행동**으로 바꾼다.  
> **청중:** 원장 + 교육 실무 + 기획/창업 혼합  
> **사용:** 대본·슬라이드·입 말로 그대로 읽어도 되게 씀

---

## 전체 한 줄

**오늘 배우는 것:** AI 유료 구독 고르는 법이 아니라,  
**“보고 → 남기고 → 다시 쓰게” 만드는 습관 3가지**와, 나중에 붙일 4가지 지도.

| 깊게 (오늘 손에 쥠) | 지도만 (이름만 알고 감) |
|---------------------|-------------------------|
| ① 들어오는 정보 정리 | ④ AI에게 시킬 때 역할 나누기 |
| ② 본 것 3줄로 남기기 | ⑤ “좋다” 전에 체크리스트 |
| ③ 자주 쓰는 AI 말에 이름 붙이기 | ⑥ 내가 진짜 센 영역 한 문장 |
| | ⑦ 팀 채널에 한 번 올리기 |

## 0. 오프닝 (14:00–14:05)

### 쉬운 제목
**오늘 90분, 무엇을 가져가나**

### 구체적으로
- 도구 설치 수업 아님  
- 코딩 수업 아님  
- **메모장/카톡/노션에 적을 수 있는 것 3개**만 가져가면 성공

### 청중이 따라 할 말
> “이번 주 안에 (1) 정보 들어오는 곳 하나 정하고, (2) 본 거 하나 3줄로 남기고, (3) AI에 자주 치는 말에 이름 하나 붙인다.”

## 1. 나의 이야기 (14:05–14:14)

### 쉬운 제목
**말로 설명 안 되는 판단이, 내 경쟁력이다**

### 구체적으로 (강연자 예시)
| 상황 | 몸이 아는 것 | 문서에 없으면 |
|------|--------------|----------------|
| 새 학생이 교재를 펼침 | “독해가 약하다/강하다” 감 | 원장 휴가면 진단이 흔들림 |
| 학부모 전화 톤 | 항의 vs 불안 vs 비교쇼핑 | 강사가 같은 전화를 못 받음 |
| 퇴원 조짐 | “요즘 숙제 안 해요” 패턴 | 티 날 때면 이미 늦음 |

### 혼합 청중용 번역 (반드시 말하기)
| 역할 | 당신 버전의 “몸이 아는 것” |
|------|---------------------------|
| **원장** | 상담·퇴원·반 배정 감각 |
| **실무** | “이 메일은 바로 올려야 한다” 순서 |
| **기획** | “이 기능은 지금 안 만든다” 판단 |

### 전환 문장
> “이 감각을 **폴더에 쌓기만** 하면 창고고, **다시 쓰이게** 만들면 시스템입니다. 그게 오늘 ①②③입니다.”

## 2. 원칙 ① — 정보 흐름 (14:14–14:28)

### 쉬운 제목 (슬라이드·입말)
**정보 들어오는 문 하나, 쌓아 두는 서랍 하나 정하기**

### 추상어 → 구체어
| 쓰지 말 것 | 대신 이렇게 |
|------------|-------------|
| 정보 흐름 시스템 | 카톡·메일·유튜브가 **한곳**으로 모이게 |
| 수집·정제·저장·재사용 | **받기 → 골라내기 → 넣어두기 → 다시 꺼내기** |
| PKM | 메모 앱 이름 아무거나 (노션/옵시디언/메모장) |

### 비유 (30초)
> 택배가 집 앞·회사·처가에 흩어지면 못 찾습니다.  
> **받는 주소 하나**를 정하는 게 ①입니다.

### 4단계를 “오늘 할 일”로
| 단계 | 오늘 적을 것 | 예시 (원장) | 예시 (실무/기획) |
|------|--------------|-------------|------------------|
| 받기 | 입구 1개 | 학부모 단톡, 교육청 메일 | 팀 슬랙 #notice |
| 골라내기 | 남길 기준 1줄 | “이번 주 상담에 쓸까?” | “이번 주 안건에 쓸까?” |
| 넣어두기 | 장소 1개 | 노션 ‘운영메모’ | 노션 ‘업무인박스’ |
| 다시 꺼내기 | 언제 볼지 | 금 20분 | 월 스크럼 전 10분 |

### 시연에서 보여줄 것
1. 앱 **원칙 #1** 화면  
2. [reasonofmoon.github.io](https://reasonofmoon.github.io/) — “여기 매일 뉴스가 **한 주소**로 쌓인다”

### 좌석 과제 (45초)
> 적기: **입구 1개** + **넣어둘 곳 1개**

### 가져가는 문장
> “많이 저장이 아니라, **받는 문·서랍·꺼내는 요일**이 있어야 한다.”

## 3. 원칙 ② — 산출물로 닫기 (14:28–14:41)

### 쉬운 제목
**보면 끝 말고, 3줄 남기고 끝**

### 추상어 → 구체어
| 쓰지 말 것 | 대신 이렇게 |
|------------|-------------|
| 산출물로 닫아라 | 본 영상/글 아래에 **제목+3줄** 쓰기 |
| 열린 루프 | 봤다는 기록만 있고 내용은 없음 |
| 최소 계약 | “나는 ○○ 보면 △△ 형식으로 □□ 안에 쓴다” |

### Hook (그대로)
> “지난달 스무 개 봤죠?  
> 그중 **옆 사람한테 3분 설명 가능한 거** 몇 개예요?”  
> **5초 침묵.**  
> “나머지는 안 사라진 게 아니라, **안 적은 겁니다.**”

### 최소 계약 양식 (칠판/슬라이드에 빈칸)
```
나는 [ 유튜브 / 기사 / 회의 ] 를 보면
[ 제목 + 핵심 3줄 + 내 생각 1줄 ] 을
[ 24시간 ] 안에 남긴다.
3줄만 써도 “끝”으로 친다.
```

### 시연에서 보여줄 것
- 앱 원칙 #2  
- Devlog **「영상으로 읽기: …」** 제목 — “형식이 같으면 나중에 검색된다”

### 좌석 과제 (40초)
> 최근 7일 본 것 1개 → 흔적 **O / X**  
> X면 그게 숙제 목록

### 역할별 3줄 예시
| 역할 | 3줄 예시 |
|------|----------|
| 원장 | (1) 학부모 불안 포인트 (2) 우리 학원 대응 한 줄 (3) 내일 할 말 |
| 실무 | (1) 결정 사항 (2) 담당 (3) 마감일 |
| 기획 | (1) 인사이트 (2) 제품에 쓸지 Y/N (3) 다음 질문 |

### 가져가는 문장
> “이해했다 = 배운 게 아니다. **3줄 남겼다 = 배운 것**이다.”

## 4. 원칙 ③ — 프롬프트 자산화 (14:41–14:55)

### 쉬운 제목
**AI에 맨날 치는 그 말, 이름 붙여 두기**

### 추상어 → 구체어
| 쓰지 말 것 | 대신 이렇게 |
|------------|-------------|
| 프롬프트 자산화 | 자주 쓰는 AI 요청을 **단축어처럼** 저장 |
| 절차 / 스킬 | “이름 있는 템플릿” |
| NAME SLOT SHAPE CHECK | 이름 · 빈칸 · 결과 모양 · 합격 기준 |

### 비유
> 카페에서 매번 “아이스 아메리카노 샷 추가 시럽 없이”를  
> 처음부터 다시 말하지 않고 **‘아아 기본’**이라고 부르는 것.

### 네 칸을 손으로 채우는 예
| 칸 | 의미 | 예시 (원장) | 예시 (실무) |
|----|------|-------------|-------------|
| **이름** | 부를 말 | `parent-reply` | `weekly-report` |
| **빈칸** | 매번 바뀌는 것 | {학부모 항의 요지} {학생 이름} | {기간} {팀} |
| **결과 모양** | 어떻게 나와야 함 | 공감 2문장 + 다음 행동 3개 | 표 3칸, 400자 이내 |
| **합격 기준** | 뭐 있으면 OK | 비난 톤 없음 / 일정 있음 | 숫자 1개 이상 |

### Hook 숫자
> 어떤 사람은 AI 대화 파일을 478개 찾아냄 → 다시 쓸 만한 건 7개.  
> **이름·빈칸·모양·기준**이 없어서 쓰레기처럼 보인 것.

### 시연
- 앱 원칙 #3  
- (선택) PCH/설명 글 — “구조만 30초”

### 좌석 과제 (50초)
> 자주 치는 AI 요청 한 줄 + **영어/한글 이름 하나**  
> 예: `상담답장`, `주간보고`, `경쟁조사`

### 가져가는 문장
> “좋은 프롬프트를 **찾지 말고**, 두 번 쓴 말에 **이름을 붙여라.**”

### 쉬운 제목
**AI에게 “알아서 해줘” 하지 말고, 역할 쪽지 주기**

| 나쁜 예 | 나은 예 |

> “프롬프트가 A4 세 장이면 글이 부족한 게 아니라 **일을 쪼개라는 신호**.”

### 시연

## 6. 원칙 ⑤ — 검증 (지도, ~2분)

### 쉬운 제목
**‘오 좋은데?’ 누르기 전에, 합격 기준 3개**

### 구체적으로
AI 결과물을 받기 **전에** 종이에:
1. **형식** — 표 3칸인가?  
2. **사실** — 출처/숫자 있나?  
3. **의도** — 내가 원한 문제 맞나?  

### 한 줄
> “예쁜 문단 ≠ 맞는 답. **미리 적은 체크리스트**가 없으면 안심한 것뿐.”

## 7. 원칙 ⑥ — 도메인 (지도, ~2분)

### 쉬운 제목
**나는 ‘전부’가 아니라 ‘이 한 줄’이 세다**

### 구체적으로 채울 빈칸
```
나는 [ 교육 / 입시 / 초등영어 / … ] 중에서
[ 누구: 고1 학부모 / 신입 강사 / … ] 에게
[ 제약: 2028 개편 / 예산 없음 / 주 1회만 … ]
이 조합이 제일 세다.
```

### 한 줄
> “구글로 나오는 지식은 값싸고, **내 상담 실패 로그·현장 감**이 비싸다.”

## 8. 원칙 ⑦ — 공개 (지도, ~2분)

### 쉬운 제목
**완성될 때까지 기다리지 말고, 팀 채널에 한 장 올리기**

### 구체적으로
| 안 해도 되는 것 | 하면 되는 것 |
|-----------------|--------------|
| 인스타 홍보 | 팀 슬랙/단톡에 워크시트 사진 |
| 완벽한 블로그 | “틀린 부분 알려주세요” 한 줄 붙이기 |

### 한 줄
> “안 올리면 틀린 줄도 모릅니다. **올리면 누가 고쳐 줍니다.**”
