**TL;DR** 다섯 자동화는 결석·보강, 민감 이슈, 신규 문의, 운영 브리핑, 숙제 미제출을 합성 데이터와 테스트 계정으로 하나씩 검증하며, 학부모 발송과 운영 결정은 사람이 맡습니다. 각 흐름은 내부 요약·분류·할 일·기록까지만 만들고, Claude in Chrome에는 운영용(production) 학생·학부모의 실명·연락처·가정 사정·상담 원문을 노출하지 않습니다. 보강 일정, 수강료·환불·퇴원·반 배정 같은 결정도 자동화 밖에 두고 사람이 원문과 정책을 확인해 실행합니다. 메일과 숙제 시트를 혼자 관리하는 학원이라면, 먼저 결과가 남을 자리를 만들고 자동화 A 한 건으로 오탐과 누락을 점검하는 편이 안전합니다.

## 시작 전에 무엇을 확인해야 하나요?

모든 계정에서 Workspace Studio와 Claude in Chrome을 쓸 수 있는 것은 아니므로, 시작 전에 접근 조건과 테스트 환경부터 확인해야 합니다. Google Workspace Studio의 접근 가능 여부는 계정 유형, Workspace 에디션, 관리자 설정, 실험 접근 여부 등에 따라 달라질 수 있습니다. 공식 시작 안내의 접근 조건을 먼저 확인하고, 계정에서 실제로 보이는 메뉴만 기준으로 삼으세요. ([Google Workspace Studio 시작 및 접근 안내](https://support.google.com/workspace-studio/answer/16444479?hl=en), 확인일: 2026-09-02)

`Claude in Chrome`은 브라우저에서 작업을 보조하는 Anthropic 기능이며, 공식 시작 안내는 유료 Claude 플랜과 서비스 가용성·시작 조건을 확인하도록 합니다. 조직의 관리자 제어와 지역·계정 조건에 따라 사용 가능 여부가 달라질 수 있으니, “설치하면 모든 계정에서 같은 화면이 나온다”고 가정하지 마세요. ([Anthropic 공식 시작 안내](https://support.claude.com/en/articles/12012173-get-started-with-claude-in-chrome), 확인일: 2026-09-02)

`Claude 학원 자동화`라는 표현을 쓰더라도, 여기서는 Claude in Chrome과 Workspace Studio의 역할을 분리합니다. Workspace Studio에서 내부 흐름을 설계하고 Claude in Chrome은 테스트 프로필에서 화면을 확인하는 보조 수단으로만 두는 것이 이 글의 권장안입니다. 두 제품이 자동으로 연결되거나 같은 권한을 공유한다고 단정하지 마세요.

공식 도움말 목차는 구성 요소와 관련 문서의 탐색 경로를 제공하지만, 버튼 이름이나 연결 순서까지 모든 계정에 고정하지는 않습니다. `Start`, `Decide`, `Ask Gemini`처럼 보이는 명칭은 이 글에서 사용하는 예시 명칭으로 보고, 현재 계정의 화면과 관리자 정책을 대조하세요. ([Google Workspace Studio 공식 도움말 목차](https://support.google.com/workspace-studio/table/17176961?hl=en), 확인일: 2026-09-02)

### 테스트 환경부터 분리하기

이 글의 권장 설계는 Chrome에 `AMP-TEST`라는 별도 프로필을 만들고, 그 프로필에만 학원 테스트 계정을 연결하는 것입니다. 실제 운영 계정의 Gmail 라벨, Drive 폴더, Chat 대화방을 그대로 쓰지 말고, 개인 테스트 계정에서 학원 테스트 계정으로만 합성 메일을 보내세요.

Claude in Chrome으로 화면을 확인할 때도 같은 테스트 프로필 안에서만 작업합니다. 실제 학생·학부모의 실명, 연락처, 가정 사정, 건강·안전 관련 내용, 상담 원문은 넣지 않습니다. Anthropic은 민감한 사이트나 다른 사람의 개인정보가 있는 페이지에서 Claude in Chrome 사용을 피하라고 안내하므로, 운영 중인 학생 명단이나 상담 화면을 열어 브라우저 조작을 시험하지 마세요. ([Anthropic 안전한 사용 안내](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely), 확인일: 2026-09-02)

준비가 끝나면 아래 다섯 가지를 기록해 두면 좋습니다.

- 테스트 프로필 이름과 테스트 계정 주소
- 관리자에게 확인한 사용 가능 플랜·정책
- 합성 데이터만 사용한다는 범위
- 테스트 결과를 저장할 폴더와 내부 Chat 대상
- 문제가 생겼을 때 해당 자동화를 끌 담당자

## 결과를 어디에 쌓아야 하나요? — 학원 업무 자동화의 기본 위치

자동화를 만들기 전에 결과 위치를 고정해야 누락과 과잉 저장을 확인할 수 있습니다. 폴더·라벨·시트를 먼저 만들면 “작동했는가”를 막연히 판단하지 않고, 어느 입력이 어느 내부 결과로 남았는지 대조할 수 있어요. 아래 이름은 제품 기본값이 아니라 이 글의 권장 예시입니다.

### 권장 저장 구조

Drive에 `학원_자동화_결과`를 만들고 다음 7개 하위 폴더를 둡니다. 학원 내부 규칙에 맞게 이름을 바꿔도 되지만, D의 운영 브리핑은 `06_운영브리핑`처럼 위치를 한 곳으로 고정하세요.

- `01_결석보강_A`
- `02_민감이슈_B`
- `03_공통수동검토`
- `04_공통검토`
- `05_숙제미제출_E`
- `06_운영브리핑_D`

`03_공통수동검토`는 사람이 수동으로 검토할 때 쓰는 조직 예시일 뿐, C 자동화가 Drive 기록을 생성한다는 뜻이 아닙니다.

Gmail 라벨은 우선 `결석·보강`, `긴급 상담`, `신규 문의` 세 개만 만듭니다. `학원_숙제현황` 시트에는 `반`, `학생`, `숙제`, `마감일`, `제출여부`, `시트 링크` 열을 두고, 실제 학생 데이터가 아닌 합성 행으로 구조를 확인하세요.

## 결석·보강 요청을 어떻게 정리하나요?

새 Gmail 메일을 분류한 뒤 필요한 값만 추출해 내부 할 일과 기록을 만들고, 보강 일정과 회신은 만들지 않습니다. 개념적인 순서는 `Gmail 새 메일 → Decide → 조건이 참일 때 Check if → Extract → Gmail 라벨 → Google Tasks → Drive 기록`입니다.

`결석·보강 자동화`의 첫 목표는 빈칸을 억지로 채우는 것이 아니라, 담당자가 확인할 항목을 빠뜨리지 않는 것입니다. 날짜나 시간은 메일에 적힌 범위만 옮기고, 일정 확정은 사람이 캘린더와 반 운영 규칙을 확인한 뒤 진행합니다.

Google Workspace Studio 공식 문서는 `Decide`와 조건에 따라 실행하는 `Check if`를 짝으로 설명합니다. 이 글의 순서는 그 공식 구성 요소를 학원용으로 조합한 권장 흐름이며, 실제 연결 카드의 배치·버튼·승인 단계는 계정에서 확인해야 합니다. ([Google Workspace Studio 조건부 단계 안내](https://support.google.com/workspace-studio/answer/16431010?hl=en), 확인일: 2026-09-02)

### 먼저 추출할 값

| 필드 | 합성 메일에서 읽을 값 예시 | 값이 없거나 불명확할 때 |
|---|---|---|
| 학생 | `테스트학생A` | 없으면 `확인 필요` |
| 반·레벨 | `초급 B반` | 언급이 없으면 `미언급` |
| 결석일 | `9월 15일` | 날짜가 충돌하면 `확인 필요` |
| 사유 | `학교 행사` | 쓰이지 않았으면 `미언급` |
| 보강 여부 | `보강 희망` 또는 `보강 불필요` | 판단할 수 없으면 `확인 필요` |
| 희망 시간 | `평일 5시 이후` | 없으면 `미언급` |
| 권장 조치 | `담당자가 가능 시간 확인` | 자동 확정하지 않고 `확인 필요` |

`미언급`은 메일에 해당 내용이 없다는 뜻이고, `확인 필요`는 표현이 모호하거나 서로 맞지 않는다는 뜻으로 구분합니다. 예를 들어 “다음 주쯤”은 날짜로 바꾸지 말고 `확인 필요`로 남겨야 합니다. 자동화가 빈칸을 그럴듯하게 채우면 이후 사람이 원문을 다시 읽을 때 오히려 혼동이 생겨요.

### 자동화 A 프롬프트 블록

아래 블록은 합성 메일 1통을 처리하는 예시입니다. 계정에 붙여넣기 전 실제 주소·이름·본문은 모두 합성 값으로 바꾸고, 출력 단계에 외부 발송 액션을 추가하지 마세요.

```text
[자동화 A: 결석·보강 요청]

[목적]
새 Gmail 메일이 결석 또는 보강 요청인지 내부적으로 분류하고 필요한 항목만 추출한다.

[입력]
테스트 계정으로 받은 Gmail 메일 1통의 제목과 본문. 실제 학생·학부모 개인정보는 입력하지 않는다.

[판단과 내부 출력]
1. 결석·보강 요청과 무관한 메일이면 처리하지 않고 테스트 로그에 '대상 아님'으로 남긴다.
2. 대상이면 학생, 반/레벨, 결석일, 사유, 보강 여부, 희망 시간을 추출한다.
3. 값이 없으면 '미언급', 모호하거나 충돌하면 '확인 필요'라고 쓴다. 추측으로 채우지 않는다.
4. 내부 요약을 만들고 Gmail '결석·보강' 라벨, 담당자 확인용 Google Task, 01_결석보강_A의 Drive 기록을 만든다.
5. 권장 조치는 '가능 시간 확인 필요'처럼 다음 사람이 확인할 일로 적는다.

[금지된 외부 행동]
보강 시간을 예약하거나 확정하지 않는다. 학부모에게 답장·문자·전화·메일을 보내지 않는다. 수강료·환불·반 배정을 결정하거나 원문 전체를 새 문서에 복사하지 않는다.

[테스트용 합성 데이터 예시]
제목: [합성 테스트] 결석 및 보강 가능 시간 문의
본문: 테스트학생A가 9월 15일 학교 행사로 결석합니다. 초급 B반이며 평일 5시 이후 보강을 희망합니다.
보낸 사람: 개인 테스트 계정
받는 사람: 학원 테스트 계정
```

저장 전에는 예시 명칭인 `Stopped` 상태를 확인하고, 권한·승인 화면이 나타나면 현재 계정의 정책을 기록합니다. `Stopped`가 모든 계정에서 같은 위치나 표시를 뜻한다고 단정하지 말고, 실행 전 비활성화 상태와 대상 계정을 직접 확인하세요.

## 민감 이슈와 신규 문의를 어떻게 나누나요?

같은 새 메일 시작점을 쓰더라도 B는 위험 신호를 내부 상담 대상으로 분류하고 C는 신규 문의 정보만 추출하도록 조건을 나눕니다. 두 흐름을 별도 테스트로 분리하면 “환불 문의를 신규 등록 문의로 잘못 기록한 경우”와 “단순 질문을 긴급 상담으로 표시한 경우”를 각각 찾기 쉽습니다.

| 구분 | 내부에서 확인할 조건 | 만드는 결과 | 사람의 후속 결정 |
|---|---|---|---|
| B. 민감 이슈 | 불만·환불·퇴원·안전 우려가 언급됐는지 신호로 표시 | 별표, `긴급 상담` 라벨, 내부 3줄 Chat 요약, Drive 기록 | 사실·긴급도 확인, 상담·환불·퇴원·안전 대응과 연락 방식 |
| C. 신규 문의 | 학년·희망 과목·레벨테스트 여부 추출; 단순 문의·결석 통보 제외 | `신규 문의` 라벨, 당일 확인 할 일 | 상담 시간, 등록 안내, 반 배정, 답장·발송 |

B의 분류는 사실이나 긴급도를 확정하는 판정이 아닙니다. “안전 우려로 보이는 표현이 있어 확인 필요”처럼 신호와 원문 근거를 남기고, 담당자가 실제 상황을 확인해야 합니다. C도 추출 결과가 곧 등록 약속이나 반 배정이 아니므로, 사람이 빈자리·상담 가능 시간과 학원 규칙을 따로 판단합니다.

```text
[테스트용 합성 데이터 예시]

본문: 테스트 계정 사용자가 환불 규정을 확인하고 상담을 요청합니다. 실제 사정과 연락처는 포함하지 않습니다.
```

```text
[자동화 C: 신규 문의 정리]

[목적]
새 Gmail 메일에서 신규 상담에 필요한 정보만 추출하고 당일 확인 할 일을 만든다.

```

오탐 점검은 세 통이면 충분한 작은 세트로 시작합니다. B에 해당하는 합성 환불 문의, C에 해당하는 합성 등록 문의, 둘 다 아닌 합성 결석 통보를 각각 넣고, B는 정의된 라벨·할 일·기록 결과를, C는 신규 문의 라벨과 당일 확인 할 일만 비교하세요. C에는 Drive 기록을 기대하지 않습니다. 분류가 언제나 정확하다고 전제하지 말고, 사람이 원문과 요약을 대조할 수 있게 근거 문장을 보존합니다.

## 매일 운영 브리핑은 어떻게 만들까요?

예약 실행으로 오늘 일정·도착 메일·미완료 할 일을 읽어 본인에게만 요약을 보내고 Drive에 기록하는 구조가 적합합니다. 권장 흐름은 `매일 예약 실행 → Ask Gemini에서 오늘 일정·도착 메일·미완료 할 일 읽기 → 본인 Chat self-DM → Drive 06 폴더 저장`입니다.

공식 문서에서 확인할 수 있는 `All sources`, Chat self-DM, Docs/Gmail 관련 구성 요소를 기준으로 흐름을 설계하되, 정확한 예약 메뉴·버튼·승인 프롬프트는 계정 화면에서 확인해야 합니다. 도움말 목차는 관련 구성 요소를 찾는 공식 경로이지, 모든 계정의 동일한 UI를 보장하는 문서는 아닙니다. ([Google Workspace Studio 공식 도움말 목차](https://support.google.com/workspace-studio/table/17176961?hl=en), 확인일: 2026-09-02)

### 브리핑 형식 고정하기

요약의 순서를 고정하면 매일 다른 문장 스타일을 비교하느라 시간을 쓰지 않습니다. 항목이 비어 있으면 내용을 만들어내지 말고 반드시 `없습니다.`라고 씁니다.

```text
오늘 수업
- 시간·수업명·내부 확인 메모

확인 필요
- 도착 메일 중 사람이 읽어야 할 항목

상담 일정
- 오늘 예정된 내부 상담

미완료 할 일
- Google Tasks의 미완료 항목
```

### 자동화 D 프롬프트 블록

```text
[자동화 D: 매일 운영 브리핑]

[목적]
오늘 하루의 내부 운영 정보를 정해진 네 구역으로 요약한다.
```

이 브리핑은 내부 참고용 메모입니다. “예약 실행이 정확히 같은 시각에 작동한다”거나 “모든 메일을 빠짐없이 읽는다”고 약속하지 말고, 실제 실행 기록·누락·중복을 확인하세요. 본인 Chat self-DM에 결과가 왔더라도, 실제 연락과 조치는 담당자가 원문과 일정 정보를 확인한 뒤 진행합니다.

## 숙제 미제출 알림은 어떻게 연결하나요?

`제출여부`가 `미제출`인 행을 내부 알림과 기록으로 연결하되 학부모에게 자동 발송하지 않습니다. 제품이 제공하는 `When a sheet changes` 시작점을 후보로 삼아 변경 감지 조건을 설정하고, 실제 계정에서 어떤 시트·범위·열 변화가 잡히는지 확인하세요. ([Google Workspace Studio 시트 변경 안내](https://support.google.com/workspace-studio/answer/16655443?hl=en), 확인일: 2026-09-02)

### 합성 시트 구조

아래 표는 실제 학생 정보가 아닌 테스트용 예시입니다. 동명이인 처리까지 확인하려면 이름을 임의로 바꾸지 말고, `테스트학생A-1`, `테스트학생A-2`처럼 합성 식별자를 사용하세요.

| 반 | 학생 | 숙제 | 마감일 | 제출여부 | 시트 링크 |
|---|---|---|---|---|---|
| 초급 B반 | 테스트학생A | Unit 2 단어 | 2026-09-15 | 미제출 | 테스트 시트의 링크 |
| 초급 B반 | 테스트학생B | Unit 2 단어 | 2026-09-15 | 제출 | 테스트 시트의 링크 |
| 중급 C반 | 테스트학생A-2 | 독해 요약 | 2026-09-16 | 미제출 | 테스트 시트의 링크 |

권장 흐름은 `시트 행 변경 → 제출여부 확인 → 반·학생·숙제·마감일·시트 링크 추출 → 본인 Chat 알림 → 05_숙제미제출_E 기록`입니다. 빈 셀은 `확인 필요`로, 언급되지 않은 값은 `미언급`으로 남깁니다. 행 식별이나 의미가 모호하면 `확인 필요`로 표시하고, 같은 이름이 두 행에 있으면 `동명이인 확인 필요`로 남겨 임의로 한 학생을 선택하지 않습니다. 담당자가 시트와 학습 상황을 확인한 뒤 지도 방법과 학부모 연락 여부·내용을 결정합니다.

### 자동화 E 프롬프트 블록

```text
[자동화 E: 숙제 미제출 내부 알림]

[목적]
학원_숙제현황 시트에서 변경된 행의 제출 상태를 확인하고 미제출 행만 내부에 알린다.

[입력]
테스트 시트의 변경된 한 행. 열은 반, 학생, 숙제, 마감일, 제출여부, 시트 링크다.

[판단과 내부 출력]
1. 제출여부가 정확히 '미제출'이면 대상이다. 다른 값이면 알림을 만들지 않고 테스트 로그에 남긴다.
2. 반, 학생, 숙제, 마감일, 시트 링크를 추출한다.
3. 빈 셀은 '확인 필요'로 쓴다. 언급되지 않은 값은 '미언급'으로 쓴다. 행 식별이나 의미가 모호하면 '확인 필요'로 쓰고, 같은 이름이 여러 행에 있으면 '동명이인 확인 필요'로 남겨 임의로 선택하지 않는다.
4. 대상 행의 요약과 시트 링크를 본인 Chat에 알리고 05_숙제미제출_E에 기록 문서를 만든다.

[금지된 외부 행동]
학부모에게 알림·답장·문자를 보내지 않는다. 학생을 혼내거나 지도 방법을 결정하지 않는다. 성적·반 배정·수강료를 변경하지 않는다.

[테스트용 합성 데이터 예시]
반: 초급 B반 / 학생: 테스트학생A / 숙제: Unit 2 단어 / 마감일: 2026-09-15 / 제출여부: 미제출 / 시트 링크: 테스트 시트의 링크
```

시트 변경 시작점은 편리해 보여도, 어떤 변경이 실제 실행을 일으키는지는 계정의 설정 화면과 테스트 결과로 확인해야 합니다. 실제 숙제 시트나 production 학생 명단을 Claude in Chrome에 열어 보여 주지 말고, 테스트 프로필의 합성 시트만 사용하세요.

## 켜기 전에 무엇을 시험해야 하나요?

합성 학생 데이터와 개인에서 학원 테스트 계정으로 보낸 메일만 사용해 자동화 하나씩 시험한 뒤 활성화합니다. Google Workspace Studio의 테스트 실행은 설정을 미리 보는 화면에 그치지 않고 실제 액션을 수행할 수 있으므로, 라벨·Tasks·Chat·Drive 문서가 바뀔 수 있다는 전제로 시험해야 합니다. ([Google Workspace Studio 테스트 실행 안내](https://support.google.com/workspace-studio/answer/16663517?hl=en), 확인일: 2026-09-02)

### 요청된 시험 순서

다음 순서를 자동화 A부터 E까지 반복합니다. 한 번에 여러 흐름을 켜면 어느 설정이 결과를 만들었는지 추적하기 어렵습니다.

1. **테스트 프로필·계정 준비**: `AMP-TEST` 프로필과 학원 테스트 계정의 Drive·Gmail·Chat·Tasks·Sheets를 확인합니다.
2. **합성 데이터 입력**: 실제 학생·학부모 이름, 연락처, 사정, 상담 원문 대신 `[합성]` 표시가 있는 메일·행·일정을 넣습니다.
3. **한 가지 자동화만 실행**: A부터 하나를 선택하고, 기존 자동화와 production 라벨·폴더를 대상에서 제외합니다.
4. **5~10분 뒤 실제 결과 확인**: 계정 화면에서 라벨, Task, Chat 메시지, Drive 기록이 만들어졌는지 봅니다. 즉시 반영이나 같은 지연 시간이 모든 계정에서 보장된다고 생각하지 않습니다.
5. **오탐·누락·권한 기록**: 참 메일과 광고성 메일을 각각 넣고 분류, 추출값, 저장 위치, 중복·누락, 권한·승인 화면을 기록합니다.
6. **`Stopped` 유지 또는 다음 단계 판단**: 결과가 기대와 다르면 비활성화 상태로 되돌리고 수정 후 다시 테스트합니다. 통과한 경우에도 다음 자동화로 넘어갈 때 이전 흐름이 켜져 있지 않은지 확인합니다.

### 자동화별 최소 시험 세트

| 흐름 | 참으로 분류할 합성 입력 | 제외하거나 경계로 둘 합성 입력 | 확인할 내부 결과 |
|---|---|---|---|
| A | 결석일·보강 희망이 있는 메일 | 광고성 학원 홍보 메일 | 라벨, 추출 필드, Task, `01` 기록 |
| B | 합성 환불·불만 문의 | 일반 자료 요청 | 별표, `긴급 상담`, 3줄 요약, `02` 기록 |
| C | 학년·과목이 있는 등록 문의 | 합성 결석 통보 | `신규 문의` 라벨, 당일 확인 할 일 |
| D | 합성 일정·메일·Task | 비어 있는 하루 | 네 구역 브리핑, self-DM, `06` 기록 |
| E | `제출여부=미제출`인 합성 행 | `제출` 행·빈 셀·동명이인 | Chat 알림, `05` 기록, 확인 필요 표시 |

테스트 계정에서 개인 계정으로 보내는 메일은 테스트 수신 주소만 사용하고, 실제 학부모 수신 주소로 보내지 않습니다. Claude in Chrome을 켠 브라우저에도 합성 데이터만 남겨야 하며, production 학생·학부모 개인정보가 보이는 탭은 열지 않습니다.

### 승인 화면은 정책의 일부로 기록하기

어떤 단계가 승인을 요청하는지, 누가 승인할 수 있는지는 조직의 보안 정책에 따라 달라질 수 있습니다. Google의 승인 요청 안내도 일부 단계의 승인 여부가 관리자 보안 설정에 좌우될 수 있음을 설명하므로, 화면에 보인 문구를 캡처하거나 기록하되 “모든 액션을 사람이 매번 자동 승인한다”고 전제하지 마세요. ([Google Workspace Studio 승인 요청 안내](https://support.google.com/workspace-studio/answer/17516423?hl=en), 확인일: 2026-09-02)

사람이 맡는 지점은 승인 버튼을 누르는 순간이 아니라, 자동화가 만든 내부 결과를 보고 보강·환불·상담·연락 같은 후속 운영 결정을 직접 검토하는 과정입니다. 테스트에서 승인 화면이 보이지 않았더라도 자동화 범위에 학부모 발송을 넣어서는 안 됩니다.

## 어디까지 자동화하고 어디서 사람이 결정하나요?

자동화는 누락 방지용 요약·분류·내부 할 일·기록까지만 맡기고 외부 커뮤니케이션과 운영 결정은 사람이 맡습니다. 아래 경계를 설계 문서에 먼저 적어 두면 프롬프트를 고치다가 실수로 외부 행동을 추가하는 일을 줄일 수 있습니다.

| 흐름 | 자동화에 남기는 일 | 사람에게 남기는 일 |
|---|---|---|
| A. 결석·보강 | 필요한 필드 추출, 라벨, Task, 기록 | 가능 시간 확인, 보강 일정 확정, 학부모 회신·발송 |
| B. 민감 이슈 | 신호 표시, 별표, `긴급 상담`, 3줄 내부 요약, 기록 | 사실·긴급도 확인, 상담·환불·퇴원·안전 대응과 연락 방식 |
| C. 신규 문의 | 학년·과목·레벨테스트 여부 추출, 라벨, 당일 할 일 | 상담 가능 시간, 등록 안내, 반 배정, 답장·발송 |
| D. 운영 브리핑 | 일정·메일·미완료 할 일의 내부 요약, self-DM, 기록 | 오늘 우선순위, 실제 연락·조치, 상담 판단 |
| E. 숙제 미제출 | 미제출 행 알림과 기록 | 학생 상황 확인, 지도 방법, 학부모 연락 여부·내용 |

Claude in Chrome은 민감한 사이트나 다른 사람의 개인정보가 있는 페이지에서 사용하지 않습니다. Anthropic의 안전 지침을 따라 별도 테스트 프로필과 합성 데이터만 사용하고, 실제 운영 학생·학부모 개인정보를 Claude in Chrome에 전송하거나 화면에 노출하지 마세요. ([Anthropic 안전한 사용 안내](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely), 확인일: 2026-09-02)

Workspace에 실제 데이터를 보관하거나 공유하는 별도 판단이 필요하다면 학원의 개인정보 처리 정책, 최소 권한, 담당자 검토를 먼저 통과해야 합니다. 이 검토가 끝났다는 이유로 production 개인정보를 Claude in Chrome에 넣어도 된다는 뜻은 아닙니다. Claude in Chrome에는 끝까지 테스트용 합성 데이터만 사용하세요.

### 활성화 전 7개 점검 항목

1. **테스트 프로필·계정**: 운영 브라우저·계정과 분리했나요?
2. **합성 학생 데이터**: 실명·연락처·가정 사정·건강·안전 내용·상담 원문이 없나요?
3. **최소 권한**: 테스트 계정이 필요한 폴더·라벨·시트만 보나요?
4. **입력·출력 위치**: A–E의 테스트 입력과 `01`~`07` 결과 위치를 기록했나요?
5. **오탐·누락**: 참 입력, 광고성·단순 입력, 빈 셀·동명이인을 확인했나요?
6. **외부 발송·운영 결정 차단**: 학부모 답장·발송, 상담·환불·퇴원·수강료·반 배정·강사 교체·안전 대응을 프롬프트에서 제외했나요?
7. **문제 발생 시 복구**: 계정 화면에서 예시 명칭인 `Turn off` 또는 비활성화 방법을 확인하고, 즉시 끈 뒤 Gmail·Drive·Chat·Tasks에 남은 영향을 확인할 담당자를 정했나요?

`Turn off` 버튼의 위치와 이후 동작은 계정마다 다를 수 있습니다. 문제가 생기면 해당 자동화를 우선 비활성화하고, 새로 생긴 라벨·Task·Chat·Drive 기록과 영향을 받은 테스트 범위를 확인하세요. 실제 운영 자료에 영향이 의심되면 임의로 지우기보다 학원 정책에 따라 담당자와 보존·복구 절차를 결정합니다.

## FAQ

### 1. 모든 계정에서 Workspace Studio와 Claude in Chrome을 쓸 수 있나요?

아니요, 계정 유형·에디션·관리자 설정·유료 플랜·서비스 가용성에 따라 접근 여부가 달라질 수 있습니다. Workspace와 Claude 각각의 공식 시작 안내를 확인한 뒤, 테스트 계정에서 실제 메뉴와 권한을 확인하세요. ([Workspace Studio 접근 안내](https://support.google.com/workspace-studio/answer/16444479?hl=en), [Claude in Chrome 시작 안내](https://support.claude.com/en/articles/12012173-get-started-with-claude-in-chrome), 확인일: 2026-09-02)

### 2. 폴더·라벨·시트를 먼저 만드는 이유는 무엇인가요?

결과 위치를 먼저 고정해야 각 입력이 어느 내부 결과로 이어졌는지 확인할 수 있습니다. 테스트 계정에서 위치를 만들면 production 자료를 건드리지 않고 누락·중복·과잉 저장도 기록하기 쉽습니다.

### 3. 테스트 실행이 실제 라벨·Tasks·문서에 영향을 줄 수 있나요?

그럴 수 있습니다. 공식 테스트 안내가 실제 액션 수행 가능성을 설명하므로, 합성 데이터와 분리된 계정으로 실행하고 라벨·Tasks·Chat·Drive 변화를 직접 확인해야 합니다. ([Google Workspace Studio 테스트 실행 안내](https://support.google.com/workspace-studio/answer/16663517?hl=en), 확인일: 2026-09-02)

### 4. Claude in Chrome에 학생·학부모 개인정보를 넣어도 되나요?

넣으면 안 됩니다. 별도 테스트 프로필에서도 실명·연락처·가정 사정·건강·안전 정보·상담 원문을 쓰지 말고 합성 데이터만 사용하세요. ([Anthropic 안전한 사용 안내](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely), 확인일: 2026-09-02)

### 5. 자동화가 학부모에게 답장을 자동으로 보내나요?

이 글의 A–E 설계는 학부모 답장·발송을 만들지 않고 내부 라벨·요약·할 일·기록까지만 남깁니다. 답장, 보강·환불·퇴원·반 배정 같은 결정은 사람이 원문과 정책을 확인한 뒤 직접 실행하며, 계정에 외부 발송 액션이 보이면 테스트 범위에서 제외하세요.

- 다섯 흐름은 내부 요약·분류·할 일·기록까지 맡기고 외부 발송은 남겨 둡니다.
- 테스트 프로필과 합성 데이터로 한 가지씩 실행해 오탐·누락·저장 위치를 확인합니다.
- 보강·환불·퇴원·반 배정·학부모 연락 같은 운영 결정은 사람이 확인하고 실행합니다.
